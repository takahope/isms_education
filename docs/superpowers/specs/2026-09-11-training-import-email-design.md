# 教育訓練匯入檔寄送功能設計

## 目標

在 `mention.html` 新增「寄送時數匯入檔」功能。管理者選擇課程後，系統預覽符合完課資格且尚未寄送的同仁資料，依 `docs/importtemplate_v20251226 (1).xlsx` 的既定結構產生 XLSX 附件，並寄給 Script Properties 指定的單一承辦同仁。成功寄送的同仁必須留下可稽核紀錄，後續批次不得重複寄送。

## 已確認需求

- 管理者必須在每次操作時明確選擇要寄送的課程，不設定預設課程。
- 僅納入同一課程中同時符合「影片觀看達標」及「測驗通過」的同仁。
- 排除離職人員與委外／合作廠商。
- 育嬰假、outside、倫理委員會成員只要完課仍納入。
- 已成功寄出的同一課程、同一 Email 不得再次寄送。
- 附件必須保存原始 XLSX 的工作表、格式、下拉驗證、註解與說明內容。
- 附件名稱使用台北時區當日日期，格式為 `importtemplate_vYYYYMMDD.xlsx`。
- 收件人與寄件人的稱呼只顯示中文名字，不顯示姓氏。
- 信件不得出現「此為系統自動發送之信件」或類似措辭。

## 方案評估

### 採用方案：保留 XLSX 並精準修改 OOXML

原始 `.xlsx` 以二進位檔案保存於 Google Drive。GAS 以 `DriveApp` 讀取 Blob，使用 `Utilities.unzip()` 解開 OOXML 套件，只修改第一張工作表的資料儲存格，再用 `Utilities.zip()` 重新封裝為 XLSX。產生的 Blob 直接交給 `MailApp.sendEmail()` 作為附件，不在 Drive 建立衍生檔案。

此方案最符合嚴格格式要求，因為除 `xl/worksheets/sheet1.xml` 的資料儲存格外，其餘 ZIP 項目均原樣保留。

### 不採用方案：轉換為 Google Sheet 後匯出

Google Sheet 的儲存格寫入較容易，但 XLSX 轉換與再次匯出可能改變資料驗證、樣式、註解、繪圖或 OOXML 內部結構，而且需要暫存檔管理與更多 Drive 權限，因此不符合嚴格範本要求。

### 不採用方案：前端 SheetJS 重建附件

前端 SheetJS 適合一般報表下載，但重建工作簿可能遺失原始範本細節。把完整附件以 Base64 經 `google.script.run` 傳回後端也增加序列化成本，且讓權威資料經過可修改的前端，不適合正式匯入檔。

## 可行性與限制

目前範本約 59 KB，包含三張可見工作表：

1. `表1-匯入資料填寫區`
2. `表2-此為範例說明(勿在此頁輸入資料)`
3. `表3-對應清單(參考用)`

表1包含 14 欄，範本預留第 2 至 1000 列，因此單次最多容納 999 位同仁。檔案沒有需要重新計算的公式；以 GAS 讀取、解壓、改寫少量 XML、重新封裝並作為郵件附件，在目前檔案大小與資料量下可行。

範本內對 `certNo` 有不一致說明：表2欄位提示允許空值，但頁面下方備註建議無證書編號時填 `0`。本功能依使用者決策留空；正式上線前須以目標系統做一次實際匯入驗證。若目標系統拒絕空值，需另行核准後才可改為數字 `0`。

`MailApp.sendEmail()` 成功返回代表 Apps Script 已接受送信要求，不代表能取得最終投遞或閱讀回條。

## 設定

Script Properties 新增兩個必要設定：

- `TRAINING_IMPORT_RECIPIENT_EMAIL`：固定收件人的公務 Email。
- `TRAINING_IMPORT_TEMPLATE_FILE_ID`：原始 `.xlsx` 在 Google Drive 的檔案 ID。

不需要 `TRAINING_IMPORT_COURSE_TITLE`；課程由管理者每次操作時選擇。

原始檔必須維持 XLSX 格式，不轉成 Google Sheet。Web App 的實際執行帳號必須具有該檔案的讀取權限。

`appsscript.json` 增加唯讀 Drive scope：

```text
https://www.googleapis.com/auth/drive.readonly
```

既有 `script.send_mail`、`spreadsheets` 與 `userinfo.email` scope 保持不變。

## 前端設計

### 入口

在 `mention.html` 頂部導覽列新增獨立按鈕「📨 寄送時數匯入檔」，與目前的「📊 匯出報告」並存。既有匯出報告、催課預覽與寄送流程不變。

### 操作流程

1. 點擊按鈕後顯示載入狀態，呼叫後端取得可選課程。
2. 彈出專用預覽視窗，課程下拉選單起始為未選取狀態。
3. 課程清單僅顯示在「訓練紀錄」與「觀看進度」都出現的非空課程名稱，依最近活動時間由新到舊排序。
4. 管理者選擇課程後，呼叫 `previewTrainingImportEmail({ courseTitle })`。
5. 切換課程時捨棄舊預覽並重新載入；載入期間不能確認寄送。
6. 預覽成功後才能點擊「確認寄送」。
7. 確認後鎖定按鈕並呼叫 `executeTrainingImportEmail({ courseTitle, previewHash })`。
8. 成功時顯示批次 ID、寄送筆數及附件檔名；失敗時保留視窗並顯示可操作的錯誤訊息。

### 預覽內容

預覽視窗顯示：

- 所選課程。
- 固定收件人 Email。
- 信件主旨與完整 HTML 內容，皆為唯讀。
- 附件檔名。
- 待寄、已寄過、寄送保留中、資料錯誤的人數。
- 本次附件表1的完整 14 欄資料，以可水平及垂直捲動的表格呈現。
- 資料錯誤清單與每筆原因。

以下任一狀況發生時，確認按鈕保持停用：

- 尚未選擇課程。
- 沒有新的待寄資料。
- Script Properties 缺漏或格式錯誤。
- 收件人或寄件人的中文姓名無法解析。
- 範本檔案、工作表或表頭驗證失敗。
- 任一待寄同仁存在資料錯誤。
- 待寄筆數超過 999。

## 後端介面與信任邊界

### `listTrainingImportCourses()`

- 驗證目前操作人具備 `DASHBOARD_ALLOWED_EMAILS` 權限。
- 讀取訓練紀錄與觀看進度。
- 回傳兩張表都有資料的課程名稱、最近活動時間與基礎筆數。
- 不接受前端提供課程清單。

### `previewTrainingImportEmail(payload)`

- 驗證操作權限。
- 驗證 `payload.courseTitle` 存在於後端產生的可選課程清單。
- 從 Script Properties 取得固定收件人與範本 ID。
- 驗證範本及建立候選資料。
- 讀取「訓練匯出紀錄」並分類待寄、已寄、準備寄送及寄送失敗資料。
- 回傳預覽資料及由權威欄位產生的 `previewHash`。

### `executeTrainingImportEmail(payload)`

- 驗證操作權限，只接受 `courseTitle` 與 `previewHash`。
- 收件人、附件資料、信件內容與姓名不得由前端提供。
- 取得 Script Lock 後重新讀取資料、匯出紀錄及範本。
- 重新建立權威資料並比對 `previewHash`；不一致時停止並要求重新預覽。
- 寫入「準備寄送」紀錄並 `SpreadsheetApp.flush()`。
- 產生附件 Blob，執行寄送，再更新該批次所有列的最終狀態。
- 無論成功或失敗都在 `finally` 釋放 Lock。

## 課程與完課資料判定

所有課程名稱先移除首尾空白，再用完整字串比對。不得把不同名稱的年度課程合併。

每位同仁、每門課的測驗狀態如下：

- 只讀取「訓練紀錄」中課程名稱完全相符的資料列。
- `測驗結果 === '通過'` 或分數大於等於 `70` 視為通過。
- 有多筆通過資料時，以最早的有效通過時間作為 `quizPassedAt`。

影片狀態如下：

- 只讀取「觀看進度」中課程名稱完全相符的資料列。
- 以該同仁、該課程的最大已觀看秒數判定，至少 `3600` 秒才達標，避免重複同步列被相加後誤判。
- 在達標資料列中，以最早的有效更新時間作為 `watchQualifiedAt`。

同時符合兩項條件後，`completedAt` 為 `quizPassedAt` 與 `watchQualifiedAt` 較晚者。任何必要時間無法解析時，該筆列為資料錯誤。

候選人必須存在於「人員主檔」、不得為離職，且不得被既有 `isVendorPersonnel_` 規則判定為委外／合作廠商。育嬰假、outside 與倫理委員會不排除。

## XLSX 欄位契約

表1第 1 列及其格式保持不變。第 2 列起先清除原範例值，再填入以下資料：

| 欄 | 欄位 | 型別與來源 |
|---|---|---|
| A | `course_title` | 文字；所選課程名稱，若尚未以 `【資安通識】` 開頭則補上該前綴 |
| B | `category_id` | 數字 `522` |
| C | `category_title` | 文字 `資通安全(通識)` |
| D | `name` | 文字；人員主檔中文姓名 |
| E | `instName` | 文字 `生醫轉譯研究中心` |
| F | `certified_hour` | 數字 `3` |
| G | `certified_date` | 文字；`completedAt` 以台北時區格式化為 `YYYY-MM-DD` |
| H | `year` | 數字；`completedAt` 的西元年 |
| I | `sso` | 文字；公務 Email 第一個 `@` 前的字串 |
| J | `tel` | 空白 |
| K | `title` | 文字 `臺灣人體生物資料庫研究人員` |
| L | `mail` | 文字；正規化後的小寫公務 Email |
| M | `typez` | 文字 `本院自辦課程` |
| N | `certNo` | 空白 |

每筆資料必須驗證姓名、Email、SSO、完成日期及所有固定必填欄位。Email 必須通過既有 Email 格式驗證。同一課程、同一正規化 Email 只保留一筆。

## XLSX 範本處理

1. 以 `DriveApp.getFileById()` 讀取 `TRAINING_IMPORT_TEMPLATE_FILE_ID`。
2. 驗證 MIME type 為 XLSX，並限制可接受的附件大小。
3. 使用 `Utilities.unzip()` 取得所有 OOXML 項目。
4. 驗證 `xl/workbook.xml` 中三個工作表名稱及順序。
5. 驗證表1第 1 列 A1:N1 完全等於既定 14 欄表頭。
6. 僅更新表1第 2 至 1000 列 A:N 的值；保留列、儲存格 style id、欄寬、自動篩選、資料驗證、註解、繪圖及其他 OOXML 項目。
7. 文字使用合法 XML escaping 與 inline string；數字欄保持 numeric cell。
8. 未使用的資料列清除值但保留格式。
9. 重新 ZIP 後設定 XLSX MIME type 及 `importtemplate_vYYYYMMDD.xlsx` 檔名。
10. 寄送前再次解壓輸出 Blob，驗證三個工作表、14 欄表頭、資料筆數及各列值與預覽雜湊來源一致。

## 姓名稱呼

固定收件人 Email 及目前操作人的 Email 都必須在「人員主檔」A 欄找到，並讀取 B 欄中文姓名。

`extractGivenName_()` 的規則為：

- 移除首尾空白及姓名內的空白。
- 姓名至少必須有兩個中文字。
- 移除第一個中文字，其餘字元作為名字。
- 無法符合上述規則時視為設定錯誤，不使用 Email、全名或通用稱呼替代。

例如「王小明」轉為「小明」。

## 信件契約

主旨：

```text
【教育訓練資料匯入】{{課程名稱}}完訓名單（{{日期}}）
```

HTML 內文：

```text
{{收件人名字}}您好：

附件為截至 {{日期}} 新增完成「{{課程名稱}}」之教育訓練資料，共 {{筆數}} 筆。名單均已符合影片觀看達標及測驗通過條件，並依全院時數管理系統匯入範本產製，請協助匯入相關系統。

附件：{{附件檔名}}
本批資料已排除先前成功寄送之紀錄。

{{寄件人名字}} 敬上
```

日期顯示為台北時區的中文日期。HTML 版本以段落及安全 escaping 呈現，另提供等義純文字 `body`。不得加入自動寄件聲明。

## 去重與寄送紀錄

在存放「訓練紀錄」的同一試算表新增「訓練匯出紀錄」。欄位如下：

1. 批次 ID
2. 唯一鍵
3. 課程名稱
4. 姓名
5. 使用者信箱
6. 完成日期
7. 收件人信箱
8. 附件檔名
9. 狀態
10. 操作者
11. 建立時間
12. 寄送時間
13. 最後更新時間
14. 錯誤訊息

唯一鍵由「未加匯入前綴的原始課程名稱」與小寫 Email 組成。狀態語意如下：

- `準備寄送`：已保留此筆，禁止自動重寄。
- `已寄出`：`MailApp.sendEmail()` 已成功返回，禁止重寄。
- `寄送失敗`：寄送呼叫拋出錯誤，後續批次可重試。

寄送前在 Lock 內再次查詢唯一鍵。建立 `準備寄送` 後必須 flush，才可呼叫 MailApp。成功後整批更新為 `已寄出`；寄送拋錯則整批更新為 `寄送失敗`。

若 MailApp 已返回但更新紀錄時中斷，紀錄會停留在 `準備寄送`，後續預覽將其列為「需人工確認」且不自動重寄。管理者確認郵件實際狀況後，可直接在工作表把狀態改成 `已寄出` 或 `寄送失敗`；本期不另建管理介面。

## 預覽一致性

`previewHash` 由以下正規化內容依固定欄位順序序列化後，以 SHA-256 建立：

- 原始課程名稱。
- 固定收件人 Email。
- 附件檔名使用的日期。
- 排序後的全部 14 欄資料列。
- 操作人及收件人的名字。

資料列依小寫 Email 排序，確保相同資料得到穩定雜湊。執行 API 在 Lock 內重新計算；日期跨日、完課資料變動、匯出紀錄變動、收件人設定變動或姓名變動，都會導致雜湊不符並要求重新預覽。

## 錯誤處理

- 權限不足：回傳固定的權限錯誤，不揭露名單或設定內容。
- 缺少 Script Property：指出缺少的 property key，禁止寄送。
- 收件人 Email 無效或查無姓名：禁止寄送。
- 寄件人查無中文姓名：禁止寄送。
- Drive 檔案不存在、無權限、MIME 錯誤或範本結構不符：禁止寄送。
- 課程不存在或只存在於其中一張資料表：禁止預覽。
- 無待寄資料：顯示已全部寄送或尚無合格同仁，不呼叫 MailApp。
- 任一候選列資料不完整：顯示全部錯誤列，整批禁止寄送。
- 超過 999 筆：整批禁止寄送，不自動拆成多封，以免破壞一次預覽對應一次附件的契約。
- MailApp 配額不足：在建立寄送保留前停止。
- MailApp 失敗：更新批次為 `寄送失敗` 並回傳錯誤摘要。
- 紀錄更新失敗：保留 `準備寄送`，禁止自動重寄並要求人工確認。

## 安全性

- `listTrainingImportCourses()`、`previewTrainingImportEmail()` 與 `executeTrainingImportEmail()` 全部重用 `canAccessMention_()` 的 default-deny 白名單。
- 前端只傳課程名稱與預覽雜湊；不得傳收件人、附件列、信件主旨、內文或姓名。
- 所有權威資料在後端重新讀取與產生。
- 範本只以 Drive ID 讀取，不建立公開 URL，不修改原檔。
- HTML 與 XML 內容分別使用對應的 escaping，避免 XSS 及破壞 OOXML。
- 寄送與唯一鍵保留位於 Script Lock 內，避免同時操作造成重複寄送。

## 測試策略

### 後端單元測試

- 課程清單只包含兩張資料表的交集，且必須由管理者明確選擇。
- 測驗通過、觀看達標、完成日期與跨課程隔離。
- 最大觀看秒數不因重複同步列相加。
- 離職及委外／合作廠商排除；育嬰假、outside、倫理委員會仍納入。
- 14 欄順序、型別、固定值、課程前綴、SSO 與空白欄位。
- 中文姓名去姓、收件人／寄件人查詢失敗。
- 唯一鍵、`已寄出`／`準備寄送` 排除及 `寄送失敗` 重試。
- 預覽雜湊因資料、日期、姓名或設定變動而失效。
- 權限、Script Properties、MailApp 配額及寄送失敗。
- Lock 取得與釋放、reservation flush 及批次狀態更新。

### XLSX 整合測試

- 使用版本庫內的原始範本 fixture 產生附件。
- 驗證 ZIP 可正常解壓，三張工作表名稱及順序不變。
- 驗證表1 A1:N1、資料列內容、資料筆數與空白尾列。
- 驗證表2、表3及表1非資料結構的 ZIP 項目未被改寫。
- 驗證資料驗證、註解、繪圖、style id 及欄寬仍存在。
- 驗證輸出檔名及 XLSX MIME type。
- 驗證範本錯誤與超過 999 筆時不產生可寄附件。

### 前端測試

- 新按鈕存在且不影響既有匯出按鈕。
- 課程沒有預設值，選擇後才載入預覽。
- 切換課程會使舊預覽與舊雜湊失效。
- 14 欄資料表、信件、統計與錯誤清單正確呈現。
- 無資料或錯誤時確認按鈕停用。
- 確認時只送出 `courseTitle` 與 `previewHash`。
- 連點防護及成功／失敗狀態恢復。

### 回歸與人工驗證

- 執行全部既有 Node 測試，確保催課、影子信箱、存取控制及目前的匯出報告不受影響。
- 將 Drive 原始範本分享給 Web App 執行帳號並完成新增 scope 授權。
